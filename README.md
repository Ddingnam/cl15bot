# cl15bot

Java 21 · Spring Boot 4.1.1 · Gradle 9.7.1 기반 Mattermost → Notion 공부 기록 봇입니다. Render Free Web Service에 Docker로 배포합니다.

```text
/study 2026-10-12 19:00 20:30 정명남 | Java 복습
/study 2026-10-12 23:00 2026-10-13 01:00 정명남 | 알고리즘
/study help
```

Members의 기존 페이지 이름을 정확히 조회하고 공용 Study Log의 `이름` 관계에 연결합니다. 새 Notion 컬럼이나 Mattermost 사용자 ID 등록은 필요 없습니다. 같은 이름이 없거나 중복이면 저장하지 않습니다. 입력한 이름으로 대상을 정하며 Mattermost 계정과 해당 멤버의 본인 여부를 대조하지 않습니다.

명령어는 환경변수 `MATTERMOST_ALLOWED_CHANNEL_ID`에 지정한 채널에서만 실행됩니다. 다른 채널·DM에서는 비공개 거절 응답을 보내고 Notion을 조회하거나 저장하지 않습니다. 자동완성 메뉴에는 다른 채널에서도 보일 수 있습니다.

## Render 배포

[배포 및 MM 테스트 안내](RENDER_DEPLOY.md)를 따릅니다. 루트의 `render.yaml`은 **Free**, **Singapore**, **master**, **Docker**, **On Commit 자동 배포**, **/actuator/health**를 지정합니다.

GitHub에 최신 코드를 올린 뒤 Render의 New → Blueprint에서 저장소와 master 브랜치를 선택하면 설정을 가져옵니다. 일반 New → Web Service로 직접 생성하는 방법도 배포 안내에 있습니다. 이미 Web Service를 만들었다면 같은 서비스를 수정하여 중복 생성하지 않습니다.

| 필수 환경변수 | 값 |
|---|---|
| MATTERMOST_SLASH_TOKEN | Mattermost /study 명령 Token |
| MATTERMOST_ALLOWED_CHANNEL_ID | 허용할 공부 기록 채널 ID (현재 `by1prkd3yty7mybdssneo4uzpw`) |
| NOTION_TOKEN | StudyPool 연결의 API 토큰 |
| NOTION_DATA_SOURCE_ID | 공용 Study Log 데이터 원본 ID |
| NOTION_MEMBERS_DATA_SOURCE_ID | Members 데이터 원본 ID |

실제 값은 Render에 입력합니다. `render.yaml`에는 다섯 변수 모두 `sync: false`로 선언하고 값을 입력받습니다. `.env.example`은 참고용이며 Spring Boot가 `.env` 파일을 자동으로 읽지는 않습니다. 제목 속성 이름을 바꾼 경우에만 선택 변수 `NOTION_TITLE_PROPERTY`를 설정합니다. 기본은 `스터디`입니다.

`MATTERMOST_ALLOWED_CHANNEL_ID`는 필수입니다. 코드에 채널 기본값이 없으며 미설정·빈 값이면 모든 채널에서 실행을 거절하고 관리자에게 설정 확인을 요청하도록 안내합니다.

## 기존 Notion 구조

StudyPool 연결에 Study Log와 Members 접근 권한과 콘텐츠 읽기/삽입 권한을 부여합니다. Members는 기존 제목 속성(ID `title`)으로 조회합니다. Study Log에 입력하는 속성은 아래 다섯 개입니다.

| 속성 이름 | 타입 | 입력 값 |
|---|---|---|
| 스터디 | 제목 | 공부 내용 |
| 이름 | 관계 → Members | 조회한 멤버 페이지 |
| 날짜 | 날짜 | 공부 시작일 |
| 시작 시간 | 날짜·시간 | 명령에서 지정한 시작 시각 |
| 종료 시간 | 날짜·시간 | 명령에서 지정한 종료 시각 |

저장 전에 Study Log 속성 정보를 읽어 기존 이름과 타입을 확인합니다. 속성 이름 앞뒤 공백은 비교할 때만 제외하고, 기록할 때는 실제 이름을 사용합니다. 공백 제외 후 이름이 중복되거나 타입이 다르면 저장하지 않습니다. Notion 컬럼 이름은 변경하지 않습니다. 총 공부 시간, 시즌 시간, Members 롤업과 랭킹은 기존 Notion 수식을 사용합니다. 봇은 계산 속성을 수정하지 않습니다. 멤버 페이지의 기존 필터 보기에 해당 기록이 표시됩니다.

날짜·시작·종료·이름·공부 내용은 필수입니다. 전체 입력은 2000자 이내입니다. 한국 시간(Asia/Seoul)으로 분 단위까지 기록하며 자정을 넘기면 시작일을 `날짜`에 넣습니다. `/study whoami`는 MM 사용자 ID 확인용이며 회원 연결에는 사용하지 않습니다. 응답은 실행한 사용자에게만 표시됩니다.

같은 날 기록은 `/study <시작일 YYYY-MM-DD> <시작 HH:mm> <종료 HH:mm> <Members 이름> | <공부 내용>`을 사용합니다. 다른 날에 끝난 기록은 `/study <시작일 YYYY-MM-DD> <시작 HH:mm> <종료일 YYYY-MM-DD> <종료 HH:mm> <Members 이름> | <공부 내용>`을 사용합니다. 같은 날에도 종료 날짜를 명시할 수 있습니다. 종료 날짜를 생략하면 시작일과 같은 날짜로만 처리하며, 종료 시각이 빠르다고 다음 날로 넘기지 않습니다. 예를 들어 `2026-10-12 23:00 2026-10-13 01:00`은 120분입니다.

종료 일시는 시작 일시보다 늦어야 하며 미래 종료를 거절합니다. 공부 시간은 1~1440분입니다. `2026-10-11 19:00 2026-10-12 19:00`처럼 종료 날짜를 명시하면 정확히 24시간도 가능합니다. 존재하지 않는 날짜, `24:00`, 잘못된 형식, 빈 이름/내용, 200자를 넘는 이름, 분만 입력하는 형식도 거절합니다. `/study help`에서 두 형식과 예시를 확인할 수 있습니다.

모든 실패 응답은 `⚠️`로 시작합니다. 입력 항목·공부 내용·구분자 누락, 날짜/시각 형식 오류와 존재하지 않는 날짜/시각에는 둘째 줄에 올바른 예시를 표시합니다. 미래 시각·같은 시작/종료·길이 제한·멤버 이름 미등록/중복·채널 제한·설정/통신 오류에는 예시 없이 이유만 표시합니다.

```text
⚠️ 날짜는 YYYY-MM-DD, 시각은 HH:mm 형식으로 입력해주세요.
예: /study 2026-10-12 19:00 20:30 정명남 | Java 복습
```

```text
⚠️ 미래 시각의 공부 기록은 입력할 수 없습니다. 공부를 마친 뒤 입력하거나 날짜·종료 시각을 확인해 수정해주세요.
```

성공 응답은 이름·시간·공부 내용 세 줄입니다. 같은 날 종료는 시각만 표시하고, 자정을 넘기면 종료 날짜도 표시합니다. 응답의 이름과 내용에 있는 줄바꿈은 공백으로 표시하며 Notion 저장 값은 그대로 유지합니다.

```text
✅ 정명남님의 공부 기록을 저장했습니다.
🕒 2026-10-13 19:00 ~ 20:30 · 90분
📚 공부 내용 : Java 복습
```

실패 안내에는 사용자 행동을 포함합니다. 입력 오류는 수정 후 재입력, 멤버 미등록은 Members 이름 확인, 중복은 Notion의 기존 기록 확인, 설정·권한 오류는 관리자 문의를 안내합니다. 저장 전 조회의 통신 실패는 잠시 후 같은 명령어로 재시도하도록 안내합니다. 저장 요청 후 결과가 불확실하면 먼저 Notion에서 해당 멤버·시간의 기록을 확인하고, 없을 때만 같은 명령어를 다시 보내도록 안내합니다. 사용자 응답에 Render Logs나 README 확인을 요구하지 않습니다.

저장 직전 같은 멤버의 Study Log에서 `기존 시작 < 새 종료`와 `기존 종료 > 새 시작`을 모두 만족하는 기록을 조회합니다. 공부 내용이 달라도 시간이 일부 겹치거나 한 구간이 다른 구간을 포함하면 새 행을 만들지 않습니다. 완전히 동일한 기록도 거절합니다. `19:00~20:00`과 `20:00~21:00`처럼 끝점만 맞닿는 기록과 다른 멤버의 기록은 허용합니다. 날짜와 한국 시간대가 포함된 ISO 8601 값으로 비교하므로 자정을 넘겨도 검사합니다. 시작/종료 시간이 없는 기존 행은 이 검사에 포함되지 않습니다. 속성 조회나 겹침 조회 실패 시에도 저장 요청을 보내지 않습니다. [Notion 필터 문서](https://developers.notion.com/reference/filter-data-source-entries)

시간 겹침 안내는 예시 없이 사용자 행동을 표시합니다.

```text
⚠️ 같은 멤버의 기존 기록과 공부 시간이 겹칩니다. 저장하지 않았습니다. Notion에서 기존 기록을 확인하고 겹치지 않는 시간으로 수정해주세요.
```

## 운영 실행과 로컬 실행

Dockerfile은 Java 21에서 테스트와 `bootJar` 빌드를 수행하고 JRE 21에서 비루트 사용자로 `app.jar`를 실행합니다. 컨테이너 실행 프로필은 `prod`, 수신 주소는 `0.0.0.0:${PORT:8080}`입니다. Render가 PORT를 제공하므로 직접 등록하지 않습니다. JVM 힙 상한은 컨테이너 메모리의 60%로 지정합니다.

개인 `application-local.*`, `application-secrets.*` 및 로컬 테스트 HTML은 배포 JAR에서 제외됩니다. 운영 프로필에서는 로컬 테스트 API도 비활성화됩니다. `.dockerignore`로 로컬 JDK·설정·환경 파일·로그·터널 스크립트를 빌드 컨텍스트에서 제외합니다.

STS에서는 [LOCAL_TEST.md](LOCAL_TEST.md)를 참고합니다. Run As → Spring Boot App으로 실행하고 실행 JRE와 Gradle JVM만 Java 21로 지정합니다. 시스템 Java 8/JAVA_HOME/PATH는 변경하지 않습니다. 로컬 화면은 STS의 `local` 프로필 또는 `bootRun`에서 사용하며 배포 JAR에는 포함하지 않습니다.

Java 21이 현재 터미널에 설정되어 있다면:

```powershell
.\gradlew.bat test bootJar --no-daemon
java -jar build/libs/app.jar --spring.profiles.active=prod
```

출력 JAR은 `build/libs/app.jar`입니다. 상태 확인 경로 `/actuator/health`는 앱 실행 상태를 보여주며 Notion 권한/저장 성공을 검증하지 않습니다.

## MVP 범위와 오류

슬래시 토큰이 다르면 HTTP 401, 미설정이면 503입니다. 입력 오류, 이름 미등록/중복, Notion 오류는 비공개 응답으로 안내합니다. Notion 400은 속성 타입, 401/403은 토큰/권한, 404는 두 데이터 원본 ID와 접근 권한을 확인합니다. 원문 API 오류와 토큰은 로그에 출력하지 않습니다.

Notion 연결 제한은 5초, 요청별 응답 제한은 8초이며 멤버 조회 → Study Log 속성 조회 → 겹침 조회 → 기록 생성 순서로 동기식 처리합니다. 자동 재시도는 없습니다. 겹침 조회와 생성은 별도 요청이므로 동시에 도착한 요청의 중복을 완전히 보장하지는 않습니다. 재입력해야 한다면 저장 여부를 먼저 확인하고 같은 날짜·시각을 명시하세요. 기록 수정/삭제, 사용자 본인 인증, 비동기 큐는 아직 지원하지 않습니다.

Render Free는 15분 동안 요청이 없으면 잠들며 재시작에 약 1분이 걸립니다. MM 테스트 전에 health 주소에서 UP을 확인합니다. 무료 한도 내 테스트용으로 사용하고 실제 키로 저장 결과를 확인하세요. [무료 정책](https://render.com/docs/free)
통신 실패는 로그에 stage=members-query 또는 stage=study-save와 예외 타입만 기록합니다. Members 조회 실패에는 저장 요청을 보내지 않았다는 응답을 반환합니다. 기록 저장 중 실패에는 저장 여부가 불확실하므로 재입력 전에 Notion을 확인합니다. MM 서버의 통합 요청 제한이 더 짧다면 관리자가 해당 제한을 확인해야 합니다.

저장 전 조회 실패는 `Notion preflight failure`와 `stage=study-schema` 또는 `stage=overlap-query`로 기록하고 저장 요청을 보내지 않았다고 안내합니다.

배포 컨테이너는 Java IPv4 소켓으로 통신합니다. IPv6 경로 문제 가능성을 제외하기 위한 설정이며, Render의 실제 경로 장애가 해결됐다는 뜻은 아닙니다. 시작 로그에서 Notion client: connectTimeout=5s requestTimeout=8s ipv4Only=true를 확인합니다.
