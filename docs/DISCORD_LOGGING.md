# Discord 공부 시간 로그

음성 자동 기록은 한 번의 이용마다 UUID 형식의 `sessionId`로 연결된 로그를 남긴다.
시작·종료·저장 구간은 한국 시간(`+09:00`)으로 출력한다. 로그 앞의 출력 시각은 실행 환경의 로그 설정을 따른다.

```text
INFO [공부입장] sessionId=... userId=... channelId=... 시작=2026-10-17T19:00:12+09:00 시작사유=방입장
INFO [공부종료] sessionId=... 종료=2026-10-17T21:30:35+09:00 실제체류=2시간30분23초 종료사유=방퇴장
INFO [공부등록완료] sessionId=... 저장시작=2026-10-17T19:00+09:00 저장종료=2026-10-17T21:30+09:00 등록분=150 등록시간=2.5
```

- `등록분`은 저장 요청의 정확한 정수 분이다. `등록시간`은 이를 60으로 나눈 값으로 소수점 네 자리까지 반올림한다.
- 시작 사유는 `방입장`, `서비스시작`, `재연결`이다. 서비스 시작 때 이미 방에 있던 사용자나 재연결 후 새로 측정해야 하는 사용자는 그 시점부터 측정한다.
- 짧은 연결 끊김은 기존 복구 정책에 따라 세션과 `sessionId`를 유지한다. 세션이 유지되면 입장·종료·등록 결과 로그를 추가하지 않는다. 기존 연결 상태·복구 로그는 별도로 출력된다.
- 종료 사유는 `방퇴장`, `봇연결끊김`, `서비스종료`이다. 복구 제한 시간 초과나 재연결 시 기존 세션 유지 불가로 종료하면 `봇연결끊김`과 마지막 정상 확인 시각을 남긴다. 서비스 종료도 기존 정책대로 마지막 확인 시각을 사용한다.
- 중복 이벤트와 공부방 사이 이동은 기존 세션을 유지하며 입장·종료 로그를 추가하지 않는다. 입장 로그의 `channelId`는 측정을 시작한 방이며, 저장에는 기존 정책대로 최근 방 정보가 사용된다.
- 3분 미만이나 지원 범위를 넘는 기록은 마지막에 `[공부등록제외]`와 제외 사유를 남긴다.
- 대기열 접수 거절은 `[공부등록실패] 사유=대기열접수거절 등록분=0`으로 남긴다.
- 저장 성공 응답이 없거나 예외가 발생하면 `[공부등록확인불가]`로 요청 구간·`요청분`을 남긴다. 경고 응답에는 저장 거절과 저장 여부 불명이 모두 포함될 수 있으므로 저장 실패로 단정하지 않는다. 같은 `sessionId`를 기존 저장 서비스 로그의 `requestId`로도 사용한다.
- 계정 미연결은 사용자당 프로세스 실행 중 한 번 `[공부측정제외] 사유=계정미연결`로 남긴다.
- 등록 결과는 사용자 DM 전송 전에 기록하므로 DM 전송 실패를 저장 실패로 오해하지 않는다.
- 강제 종료·장애 시 후속 로그를 남기지 못할 수 있다. 기존 세션은 메모리에만 유지된다.

이 변경은 기존 측정·저장 정책을 유지하고 서버 로그만 추가한다. Discord·Notion 추가 API 호출이나 주기적 조회는 없다.
정상 이용당 세 줄의 세션 로그 외에 기존 라이브러리·저장 서비스 로그가 함께 출력될 수 있다.
로그에는 사용자·채널 ID가 포함되며, 사용자 이름·공부 내용·인증 정보·응답 본문은 추가하지 않는다.
