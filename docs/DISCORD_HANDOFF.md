# Discord 공부방 자동 기록 구현 인수인계

작성일: 2026-10-13 (한국 시간)

## 작업 목적과 현재 결정

현재 Mattermost 명령어로 공부 기록을 Notion에 저장하는 MVP가 있다. 날짜·시간·이름을 모두 입력하던 초기 방식에서 2026년 MMDD·HHmm 입력과 이름 자동 매칭으로 단축했다. 날짜·시간 직접 입력 부담은 남아 있어, 추후 Discord로 이동하면 공부방 체류 시간을 자동으로 기록한다.

Discord Gateway 연결·자동 기록·DM 기능을 1차 구현했다. 실행 준비와 테스트 절차는 [DISCORD_SETUP.md](DISCORD_SETUP.md)를 참고한다. 영구 상태·보류 재처리는 후속 단계다.

Discord 수동 `/st`도 구현했다. Discord의 `입력` 옵션에 MM과 동일한 날짜·시간·내용 또는 `도움말`·`내정보`를 넣는다. 공통 파서와 저장 서비스를 사용하며 수동 최소 시간은 MM과 같은 1분이다. 지정 서버에 자동 등록하고 모든 수동 응답은 ephemeral로 표시한다. 음성 자동 기록의 DM·3분 기준과 구분한다.

- 측정 대상은 지정된 **Discord 음성 채널의 접속 시간**이다.
- 실제 목소리, 발언 여부, 마이크, 카메라를 분석하지 않는다. 마이크를 꺼도 공부 시간으로 인정한다.
- 참가자를 신뢰하는 운영 방침이다. 체류 시간을 실제 집중 공부의 증명으로 해석하지 않는다.
- 일반 텍스트 채널을 열어둔 시간은 이 방식으로 측정할 수 없다.
- 매초 접속 여부를 조회하지 않는다. 입장·퇴장·채널 이동 이벤트로 시간을 계산한다.
- Discord 계정과 Notion Members 페이지를 연결하여 이름을 매번 입력하지 않게 한다.
- 날짜·시작·종료 시간은 자동으로 생성한다. 공부 내용은 `모각코`로 통일하고 수정은 Notion에서 수기로 한다.

## 현재 프로젝트

- 저장소: https://github.com/Ddingnam/cl15bot
- 브랜치: `master`
- Java 21 / Spring Boot 4.1.1 / Gradle
- 현재 배포: Render Free, Docker
- 현재 명령어 API: `POST /api/mattermost/study`
- 현재 상태 확인: `/actuator/health`
- Mattermost 채널 제한은 제거되어 있다. 응답은 실행한 사용자에게만 표시한다.
- 저장 성공 시 Notion 링크를 표시하고, 시간 겹침 시 기존 기록의 시간대와 링크를 표시한다.
- Mattermost의 `response_url`이 있으면 처리 중 안내 후 백그라운드 작업 결과를 전송한다.

현재 수동 입력 형식:

```text
/st 1013 1900 2030 Java 복습
/st 1013 2300 1014 0100 Java 복습
```

연도 생략(2026년 고정), 짧은 `/st`, MMDD·HHmm 네 자리 입력과 환경변수 MATTERMOST_MEMBER_MAPPINGS에 의한 이름 매칭은 구현되었다. 관리자가 MM 사용자 ID → Members 이름을 최초 등록한다. Discord는 `DISCORD_MEMBER_MAPPINGS`에 별도로 등록한다. 사용자 최초 1회 연결 명령과 `/시작`·`/종료`는 구현하지 않는다.

## 기존 Notion 구조와 재사용 코드

공용 `Study Log` 데이터 원본에 행을 생성한다. `이름` 관계 속성으로 `Members` 페이지에 연결한다. 각 멤버 페이지의 Study Log는 필터된 보기이며, 멤버마다 별도 데이터베이스를 만들지 않는다.

기존 기록 속성:

| 속성 | 타입 | 자동 기록 값 |
|---|---|---|
| 스터디 | 제목 | 기본 공부 내용 또는 사용자가 지정한 내용 |
| 날짜 | 날짜 | 운영 기준에 따른 기록일 |
| 이름 | 관계 | 연결된 Members 페이지 ID |
| 시작 시간 | 날짜·시간 | 공부방 입장 시각 |
| 종료 시간 | 날짜·시간 | 퇴장 또는 휴식방 이동 시각 |

속성 이름에 뒤 공백이 있는 경우가 있다. 기존 코드처럼 이름을 비교할 때만 공백을 제거하고, 쓰기에는 실제 속성 이름을 사용한다. 기존 수식·롤업·랭킹 속성은 수정하지 않는다.

검토할 코드:

- `src/main/java/com/example/cl15bot/StudyEntry.java`: 한국 시간과 시작/종료 시간 모델. 현재 수동 입력은 1~1440분, 미래 종료 금지.
- `src/main/java/com/example/cl15bot/NotionStudyClient.java`: Members 조회, 속성 확인, 시간 겹침 검사, 기록 생성, Notion 링크 반환.
- `src/main/java/com/example/cl15bot/MemberRegistry.java`: 멤버 조회.
- `src/main/java/com/example/cl15bot/MattermostMemberMapping.java`: 환경변수의 MM 사용자 ID → Members 이름 매칭. Discord 사용자 ID 매칭은 별도로 설계한다.
- `src/main/java/com/example/cl15bot/StudyCommandController.java`: Mattermost 입력과 결과 안내. Discord 이벤트 로직을 이 컨트롤러에 섞지 않는다.
- `src/main/java/com/example/cl15bot/MattermostResponseSender.java`: Mattermost 전용 결과 전송. Discord 응답 구현과 분리한다.

플랫폼별 입력 처리는 분리하고, `StudyRecordingService`에서 공통 공부 기록 저장과 멤버별 동시 처리 제한을 수행한다. Discord의 `DiscordStudySessions`는 자동 기록을 생성하며 수동 명령어 파서를 거치지 않는다. `DiscordBot`이 Gateway 이벤트와 DM 전송을 담당한다.

## 입장·퇴장 처리 흐름

Discord Gateway의 `VOICE_STATE_UPDATE`와 `GUILD_VOICE_STATES` intent를 사용한다. 음성 데이터 수신·녹음 기능은 필요 없다.

사용자마다 직전 채널과 새 채널을 비교한다. 같은 채널에서 마이크·헤드셋 상태만 바뀐 이벤트는 시작/종료로 처리하지 않는다.

| 변화 | 처리 |
|---|---|
| 공부방 밖 → 공부방 | 시작 시각과 세션을 저장 |
| 공부방 → 동일 공부방 | 유지. 음소거 변경 등으로 시간을 초기화하지 않음 |
| 공부방 → 휴식방 또는 다른 일반 채널 | 세션 종료 후 저장 작업 접수 |
| 공부방 → 연결 해제 | 세션 종료 후 저장 작업 접수 |
| 공부방 A → 공부방 B | 지정 서버의 일반 음성 채널 간 이동은 같은 세션 유지 |
| 공부방 밖 → 공부방 밖 | 처리하지 않음 |

예시:

```text
19:00 공부방 입장 → 시작 시각 저장
19:20 마이크 끄기 → 기존 세션 유지
20:30 공부방 퇴장 → 90분 기록 → Notion 링크 안내
```

체류 중 경과 시간은 `현재 시각 - 시작 시각`으로 계산한다. 표시용 타이머를 갱신하더라도 매초 Discord API를 호출하지 않는다.

## 확정 운영 규칙 — 1차 구현·무료 테스트

2026-10-13 대화에서 아래 규칙을 확정했다. 이 절의 결정이 아래의 장기 운영 설계 제안보다 우선한다.

1. **계정 연결:** `DISCORD_MEMBER_MAPPINGS` 환경변수의 Discord 사용자 ID → 기존 Notion Members 이름 JSON을 사용한다. 같은 Notion 멤버에는 계정 하나만 허용하며 중복 이름 매핑은 설정 오류로 처리한다. 사용자는 박지원의 중복 계정 하나를 이미 제거했다. Notion 컬럼은 추가하지 않는다.
2. **범위:** 지정 서버의 모든 일반 음성 채널을 측정하며 새 채널도 포함한다. Stage 채널과 봇 계정은 제외한다. 휴식방은 별도로 두지 않는다.
3. **내용:** `모각코`로 저장한다. 내용 수정은 Notion에서 수기로 한다.
4. **세션:** 입장 시 시작, 음성 연결 해제 시 종료한다. 서버 내 대상 음성 채널 간 이동은 같은 세션을 유지한다. 음소거·카메라 상태 변화는 무시한다. 연결 해제 후 재접속은 별도 세션이며 끊긴 시간은 제외한다.
5. **시간:** 초를 버리기 전 실제 체류가 3분 미만이면 저장하지 않는다. 3분 이상은 전체 구간을 기록한다. 저장할 시작·종료 시각의 초를 버리고 분 단위로 계산한다. 한국 시간 기준, 자정에 분리하지 않고 한 행으로 저장하며 날짜는 시작일이다. MM과 동일하게 2026년 고정, 연도 경계 기록 거절, 최대 24시간이다. 최대 시간과 연도 검증은 MM과 같은 저장 구간 기준을 사용한다.
6. **겹침:** 같은 Notion 멤버의 기존 MM·Discord 기록과 일부라도 겹치면 전체 저장을 거절한다. 끝점만 맞닿으면 허용한다. 측정한 시작·종료 시각과 겹친 기존 기록 링크를 DM으로 안내한다.
7. **알림:** 저장 결과는 개인 DM으로 보낸다. 3분 미만 기록은 DM 없이 제외한다. 미등록 사용자는 기록에서 제외하고 연결 필요 안내를 앱 실행 중 사용자당 한 번만 보낸다. 재시작하면 안내 제한은 초기화될 수 있다. DM 실패는 로그에만 남기며 완료된 Notion 저장을 취소하거나 재실행하지 않는다.
8. **중단:** 정상 Gateway 연결 중 heartbeat 응답으로 마지막 확인 시각을 갱신하되 사용자별 API 반복 조회는 하지 않는다. 봇 연결 단절 시 최대 2분 동안 기록을 보류한다. 기존 Gateway 세션 복구는 밀린 입·퇴장 이벤트를 수신 순서·수신 시각으로 반영한다. 새 세션 생성은 준비된 음성방 상태와 대조하며 같은 방에 남은 사람의 시작 시각을 유지하고 짧은 장애 시간을 포함한다. 새 세션에서는 장애 중 퇴장·재입장을 구분할 수 없다. 접속 상태가 다르거나 2분 내 복구하지 못하면 마지막 정상 확인 시각까지 종료하고 결과 DM에 장애 안내를 붙인다. 종료 타이머는 복구 시 취소하고 이전 타이머가 새 장애의 기록을 종료하지 못하도록 세대를 확인한다. 종료 코드·서버 종료 여부·세션 복구/재생성·보류/복구 인원을 로그에 남긴다. 상태는 메모리에만 보관하므로 앱 자체 재시작 시 이전 시작 시각은 복구하지 못한다. 재시작 후 봇 준비 완료 시점부터 현재 접속자를 새로 측정한다.
9. **동시 처리:** 중복 종료 이벤트는 같은 실행 중 한 번만 처리한다. MM·Discord 저장은 Discord ID가 아닌 공통 Notion 멤버 기준으로 순서대로 처리하며 겹침 조회와 저장을 같은 처리 범위에 둔다.
10. **불확실한 저장:** Notion 생성 결과를 확인하지 못하면 자동으로 다시 생성하지 않는다. DM으로 Notion 확인 후 수동 처리를 안내한다. 조회 재시도와 생성 재시도를 구분한다.
11. **후속 개발:** 영구 세션·저장 작업 보관, 겹침 보류 DB, 재처리 명령은 상시 운영 전환 때 추가한다. 1차는 재시작 시 진행 중·대기 기록 유실과 거절 기록의 자동 복구 불가를 허용하는 기능 테스트 단계다.

## 재시작·중복·통신 실패 처리

현재 구현에서 이미 확인된 한계를 자동 기록 설계에 반영한다.

- 기존 겹침 검사는 `기존 시작 < 새 종료 AND 기존 종료 > 새 시작`이다. 끝점만 맞닿는 구간은 허용한다.
- 조회와 생성이 별도 요청이어서 동시 입력이 두 행을 만들 수 있다. 자동 기록은 사용자별 처리 순서와 세션 ID 기반 중복 방지를 함께 설계한다.
- 시작 시각과 저장 대기 작업을 메모리에만 두면 봇 재시작 시 유실된다. 상시 운영에서는 영구 저장 가능한 세션·작업 상태가 필요하다.
- 세션 상태는 예를 들어 `진행 중 → 종료됨/저장 대기 → 저장 완료`로 관리하고, 완료 후 Notion 페이지 ID와 URL을 보관한다.
- Notion 저장 직후 응답을 받기 전에 끊길 수 있다. 단순 재전송은 중복을 만들 수 있으므로 저장 여부 확인과 중복 방지를 먼저 설계한다.
- Gateway 재연결 시 세션 재개와 현재 접속 상태를 확인한다. 이벤트를 놓쳤을 수 있는 시간의 퇴장 시각을 정확히 복원할 수 있다고 가정하지 않는다. 확인 불가능한 구간의 인정 기준을 정한다.
- 접속 이벤트를 중복 수신하거나 같은 세션 종료 처리가 반복되어도 저장 작업은 하나만 생성하도록 한다.
- Notion의 `Retry-After`를 존중하며 요청 속도와 재시도 횟수를 제한한다. 조회·결과 전송 재시도와 기록 생성 재시도를 구분한다.
- 결과 메시지 전달 실패는 Notion 저장 실패와 구분한다. 현재 Mattermost 응답 전송은 HTTP 302를 실패로 감지하지 못하는 문제가 확인되어 있으며, 별도 보완 대상으로 남아 있다.

## 호스팅과 비용

무료 운영이 우선이라는 기존 요구를 유지한다.

현재 Render Free Web Service는 15분 동안 들어오는 요청이 없으면 절전한다. Discord Gateway는 봇이 여는 지속적인 WebSocket 연결이므로, 이 연결만으로 Render Free가 항상 깨어 있을 것이라고 가정하지 않는다.

Discord 자동 기록에는 상시 실행 가능한 호스팅을 먼저 검토한다. 무료 제공 여부·한도는 구현 시점에 다시 확인한다. 유료 플랜 선택이나 결제 설정은 사용자의 별도 승인을 받는다. 주기적인 요청으로 무료 서버를 강제로 깨우는 방식에 의존하지 않는다.

현재 수동 Mattermost 서비스는 유지할 수 있다. Discord 자동 기록과 수동 입력이 같은 Notion 저장 서비스를 공유하도록 설계한다.

1. 저장소를 clone하거나 기존 checkout의 `master`를 최신화한다.
2. 이 문서, `README.md`, `LOCAL_TEST.md`, `RENDER_DEPLOY.md`와 위 관련 코드를 읽는다.
3. 실행 JRE와 Gradle JVM을 Java 21로 지정한다. 수업용 Java 8 및 시스템 `JAVA_HOME`/`PATH`는 유지한다.
4. 기존 Notion 설정은 새 PC에서 따로 등록한다. 실제 토큰은 Git에 없다.

```text
NOTION_TOKEN
NOTION_DATA_SOURCE_ID          # 공용 Study Log
NOTION_MEMBERS_DATA_SOURCE_ID  # Members
MATTERMOST_SLASH_TOKEN         # 기존 MM 기능도 실행할 경우
MATTERMOST_MEMBER_MAPPINGS     # MM 사용자 ID → Members 이름 JSON
```

Discord 설정은 `DISCORD_BOT_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_MEMBER_MAPPINGS`이다. 모든 일반 음성 채널을 사용하므로 채널 목록은 필요 없다. 실제 키를 Markdown, 소스 코드, 커밋, 로그에 적지 않는다.

이전 `MATTERMOST_ALLOWED_CHANNEL_ID`는 더 이상 사용하지 않는다.

5. Java 21 환경에서 기존 테스트와 빌드를 실행해 기준 상태를 확인한다.

```powershell
.\gradlew.bat test bootJar --no-daemon
```

짧은 명령어 변경 이후의 테스트 상태와 수는 최신 빌드 결과를 확인한다. 실제 Docker 빌드는 외부 라이브러리 저장소의 Maven Central 429로 실패한 이력이 있다. 테스트 실패와 다운로드 제한을 구분한다.

## 권장 구현 순서와 검증

1. 계정 연결과 공부방 운영 규칙을 확정한다.
2. 상시 실행 호스팅과 세션 보관 방법을 정한다.
3. 기존 Notion 저장 처리를 공통 서비스로 분리한다.
4. Discord 입장·퇴장·이동 이벤트를 받아 세션을 관리한다.
5. 종료된 세션을 기존 Notion 구조에 저장하고 결과 링크를 안내한다.
6. 재시작 복구·중복 방지·통신 실패 처리를 검증한다.

필수 검증 사례:

- 입장 후 퇴장 시 정확한 시간으로 한 행 생성.
- 마이크·헤드셋 상태 변화로 세션이 나뉘지 않음.
- 휴식방·일반 채널에서는 시간이 쌓이지 않음.
- 대상 공부방 간 이동과 짧은 재접속이 확정된 규칙대로 동작.
- 동일 종료 이벤트 반복과 동시 수동 입력이 중복 기록을 만들지 않음.
- 자정·시즌 경계·24시간 이상·1분 미만 체류가 규칙대로 처리.
- 봇 재시작 중인 세션과 저장 대기 작업 복구.
- Notion 저장 결과가 불확실할 때 무조건 다시 생성하지 않음.
- 메시지 전달 실패와 저장 실패가 구분됨.
